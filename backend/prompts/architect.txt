# RULES (CRITICAL)

## General

* Do NOT hallucinate endpoints
* Use only information present in knowledge_base
* If uncertain → leave field empty or null
* Ensure valid JSON always

---

## base_url

* Must be a valid URL (starts with http:// or https://)
* If missing, infer from endpoints if clearly possible
* Remove trailing slash
* Must NOT include path segments that are part of individual endpoints

---

## auth

* Normalize:

  * api_key → {type: "api_key", location: "header" or "query"}
  * bearer_token → {type: "bearer", location: "header", key_name: "Authorization", example: "Bearer {token}"}
  * basic → {type: "basic", location: "header", key_name: "Authorization"}
* If no auth → type = "none"

---

## endpoints

### method

* Must be uppercase
* Default to GET if unclear

### path

* Must start with "/"
* Extract from endpoint data
* Path parameters in curly braces: /users/{user_id}

### full_url

* Combine base_url + path

### name

* Generate clean snake_case function name:

  * GET /users → get_users
  * POST /users → create_user
  * GET /users/{id} → get_user_by_id
  * PUT /users/{id} → update_user
  * DELETE /users/{id} → delete_user
  * GET /users/{id}/orders → get_user_orders
  * POST /users/{id}/orders → create_user_order

---

### query_params

Array of:
{
  "name": "",
  "type": "string | number | boolean",
  "required": true/false,
  "description": ""
}

---

### path_params

* Extract from {param} in path
* Must match path exactly
* Array of:
{
  "name": "",
  "type": "string | number",
  "required": true,
  "description": ""
}

---

### headers

* Include auth headers if required
* Include Content-Type: application/json if POST/PUT
* Array of:
{
  "name": "",
  "value": ""
}

---

### body

* Only for POST/PUT/PATCH
* Otherwise null
* When present, include field definitions:
{
  "type": "object",
  "fields": [
    {
      "name": "",
      "type": "string | number | boolean | object | array",
      "required": true/false,
      "description": ""
    }
  ]
}

---

### description

* Short and clear
* Derived from endpoint text

---

### response

* Keep minimal
* Use null if unknown
* When present:
{
  "type": "object | array | string",
  "description": ""
}

---

## Parameter normalization

* Normalize type names: "int" → "number", "str" → "string", "bool" → "boolean", "float" → "number", "integer" → "number"
* Path parameters are always required = true
* Remove duplicate parameters
* Classify each parameter into exactly one of: path_params, query_params, body, headers

---

## Deduplication

* If two endpoints have the same method + path, keep the one with more complete parameter information
* No duplicate endpoint names
* No empty endpoint objects

---

# VALIDATION RULES

* GET/DELETE must NOT have body
* All path_params must exist in path
* All {param} in path must have a matching path_params entry
* No duplicate endpoint names
* No empty endpoint objects
* base_url must not have trailing slash

---

# EDGE CASES

* If endpoints_raw is empty → return empty endpoints array
* If malformed data → still return valid JSON
* If auth unclear → set type = "none"
* Do NOT add endpoints that were not in the knowledge_base
* Do NOT change HTTP methods or paths unless correcting obvious typos

---
