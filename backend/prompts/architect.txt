## NORMALIZATION RULES

1. Every endpoint MUST have:
   - name: a camelCase function name derived from the path and method (e.g., GET /users → getUsers, POST /users/{id}/orders → createUserOrder)
   - method: uppercase HTTP method (GET, POST, PUT, PATCH, DELETE)
   - path: the endpoint path with path parameters in curly braces (e.g., "/v1/users/{user_id}")
   - params: array of parameter objects (can be empty)
   - headers: array of required header objects (can be empty)
   - description: one-line description of what the endpoint does

2. Parameter normalization:
   - Each param must have: name, location (path|query|body|header), type (string|integer|number|boolean|object|array), required (boolean)
   - Path parameters are always required
   - Remove duplicate parameters
   - Normalize type names: "int" → "integer", "str" → "string", "bool" → "boolean", "float" → "number"

3. Auth handling:
   - Copy the auth block from knowledge_base as-is
   - If auth.type is "bearer_token", add a default header: {"name": "Authorization", "value": "Bearer {token}"}
   - If auth.type is "api_key" and auth.location is "header", add a default header with the key_name

4. Base URL:
   - Must include scheme (https://)
   - Must NOT have a trailing slash
   - Must NOT include path segments that are part of individual endpoints

5. Deduplication:
   - If two endpoints have the same method + path, keep the one with more complete parameter information
   - Log deduplication in the description field

6. Do NOT add endpoints that were not in the knowledge_base.
7. Do NOT change HTTP methods or paths unless correcting obvious typos (document any changes).

## OUTPUT FORMAT
Respond with ONLY this JSON object. No text before or after.

        }

    }
