### 1. client.py

Requirements:
- Use `httpx` for HTTP requests (both sync and async)
- Create a class named `{ApiName}Client` (PascalCase derived from api_name)
- Constructor accepts: `base_url: str = "{base_url}"`, `api_key: str = ""`, `timeout: float = 30.0`
- Store auth credentials and inject them into every request based on the auth config
- One method per endpoint, named using the endpoint's `name` field (snake_case from api_schema)
- Method signature: all `path_params` and required `query_params` as positional args, optional `query_params` as keyword args with defaults
- Path parameters (from `path_params`) must be interpolated into the URL path
- Query parameters (from `query_params`) must be passed as `params` dict to httpx
- Body (from `body` field, only for POST/PUT/PATCH) must be passed as `json` dict to httpx
- Every method must have a docstring with the endpoint description
- Every method must return `httpx.Response`
- Include proper error handling: raise `httpx.HTTPStatusError` on 4xx/5xx
- Type hints on all parameters and return values
- No placeholder code — every method must be fully implemented

### 2. models.py

Requirements:
- Use `dataclasses` with `@dataclass` decorator
- Create request/response models for endpoints that have body parameters
- Use Python type hints (str, int, float, bool, list, dict, Optional)
- Include a `to_dict()` method on each model
- Include a `@classmethod from_dict(cls, data: dict)` factory method
- Import `Optional` from typing where needed

### 3. tests/test_client.py

Requirements:
- Use `pytest` and `unittest.mock`

  - Correct query/body params passed
- At least one test per endpoint
- Tests must be runnable without any API key or network access
- Include proper assertions on mock calls
