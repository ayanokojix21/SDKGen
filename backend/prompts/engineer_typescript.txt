## FILES TO GENERATE

You must generate exactly 4 files. Return them as a JSON object where keys are filenames and values are the complete file contents as strings.

### 1. client.ts

Requirements:
- Use the native `fetch` API for HTTP requests
- Create a class named `{ApiName}Client` (PascalCase derived from api_name)
- Constructor accepts: `config: ClientConfig` where ClientConfig is an interface with `baseUrl: string`, `apiKey: string`, `timeout?: number`
- Store auth credentials and inject them into every request based on the auth config
- One async method per endpoint, named using the endpoint's `name` field (snake_case from api_schema)
- Method signature: all `path_params` and required `query_params` as positional args, optional `query_params` in an options object
- Path parameters (from `path_params`) must be interpolated into the URL path using template literals
- Query parameters (from `query_params`) must be appended to the URL using `URLSearchParams`
- Body (from `body` field, only for POST/PUT/PATCH) must be passed as `JSON.stringify(body)` with `Content-Type: application/json`
- Every method must have a JSDoc comment with the endpoint description
- Every method must return `Promise<Response>` or a typed response if the `response` field is available in the schema
- Include error handling: throw an error on non-ok responses with status code and body
- Strict TypeScript types on all parameters and return values
- No placeholder code — every method must be fully implemented
- All methods must use `async/await`

### 2. models.ts

Requirements:
- Use TypeScript `interface` for all models (not `type` aliases)
- Create request/response interfaces for endpoints that have body parameters
- Use strict types: `string`, `number`, `boolean`, `Record<string, unknown>`, arrays
- Export all interfaces
- Use `readonly` for response model fields
- No `any` type — use `unknown` if type is uncertain

### 3. tests/test_client.ts

Requirements:
- Use a test structure compatible with Jest or Vitest
- Mock `global.fetch` using `jest.fn()` or `vi.fn()`
- Test every client method with:
  - Correct URL construction (path params interpolated, query params appended)
  - Correct HTTP method used
  - Correct headers sent (including auth)
  - Correct body serialization
- At least one test per endpoint
- Tests must be runnable without any API key or network access
- Include proper assertions on mock calls
- Use `beforeEach` to reset mocks

### 4. README.md

Requirements:
- Title: `# {api_name} TypeScript SDK`
- Sections: Installation, Authentication, Quick Start, API Reference
- Installation section: mention no external deps needed (uses native fetch)
- Authentication section: show how to initialize the client with credentials
- Quick Start: show a working async/await code example calling one endpoint
- API Reference: table with columns: Method, Endpoint, Description
- All code examples must use the actual class and method names from client.ts

## CRITICAL RULES
- No syntax errors. Every file must compile with `tsc --strict`.
- No incomplete methods. Every method body must be fully implemented.
- No placeholder comments like "// TODO" or empty function bodies.
- No hardcoded API keys or secrets.
- No `any` type anywhere in the codebase.
- Imports/exports must be consistent across files.
- Use `const` by default, `let` only when reassignment is needed, never `var`.
